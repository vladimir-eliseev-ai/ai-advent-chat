# AI Advent Chat

Android приложение для общения с AI, поддерживающее **DeepSeek API** (облачный) и **Ollama** (локальный), построенное с использованием Jetpack Compose и современных Android практик.

## 🚀 Технологии

- **UI**: Jetpack Compose + Material Design 3
- **Архитектура**: Clean Architecture + MVVM
- **Сеть**: Retrofit 2 + Kotlinx Serialization
- **DI**: Hilt
- **Асинхронность**: Kotlin Coroutines + Flow
- **Логирование**: Timber

## 📋 Требования

- Android Studio Hedgehog или новее
- JDK 11 или выше
- Min SDK: 24 (Android 7.0)
- Target SDK: 36
- Kotlin 2.0.21

## ⚙️ Настройка

Приложение поддерживает два режима работы:

### Вариант 1: DeepSeek API (облачный, рекомендуется для начала)

1. Перейдите на [Deepseek Platform](https://platform.deepseek.com/api_keys)
2. Зарегистрируйтесь или войдите в аккаунт
3. Создайте новый API ключ
4. Добавьте ключ в `local.properties`:

```properties
DEEPSEEK_API_KEY=ваш_api_ключ_здесь
OLLAMA_BASE_URL=http://10.0.2.2:11434/
```

### Вариант 2: Ollama (локальный, бесплатный)

1. Установите Ollama на вашем компьютере: https://ollama.ai
2. Запустите сервер: `ollama serve`
3. Загрузите модель: `ollama pull llama3.2:1b`
4. Настройте URL в `local.properties`:

```properties
DEEPSEEK_API_KEY=sk-any_value_for_build
OLLAMA_BASE_URL=http://10.0.2.2:11434/
```

**Важно:** Для реального устройства замените `10.0.2.2` на IP вашего компьютера.

📖 **Подробная инструкция по Ollama:** См. [OLLAMA_SETUP.md](OLLAMA_SETUP.md)

### 3. Синхронизация проекта

1. Откройте проект в Android Studio
2. Дождитесь завершения индексации
3. Нажмите **File → Sync Project with Gradle Files** (или кнопку Sync в панели уведомлений)
4. Дождитесь завершения синхронизации

### 4. Запуск приложения

1. Подключите Android устройство или запустите эмулятор
2. Нажмите **Run** (▶️) или используйте горячую клавишу `Shift + F10`
3. Дождитесь установки и запуска приложения

## 📱 Использование

### Основные функции

1. **Отправка сообщений**: Введите текст в поле ввода и нажмите кнопку отправки
2. **Просмотр истории**: Все сообщения отображаются в хронологическом порядке
3. **Индикатор загрузки**: При ожидании ответа от AI отображается индикатор загрузки
4. **Обработка ошибок**: Ошибки отображаются через Snackbar с понятными сообщениями

### Настройки (иконка ⚙️)

1. **System Prompt** - настройка системного промпта
2. **Температура** - управление креативностью ответов (0 = точный, 1.2 = креативный)
3. **API провайдер и модель** - переключение между DeepSeek и Ollama, выбор модели

### Выбор API провайдера

В настройках можно выбрать:
- **DeepSeek** - облачный API (требует ключ, платный но дешевый)
- **Ollama (локальный)** - локальные модели (бесплатно, работает офлайн)

### Доступные модели

**DeepSeek:**
- `deepseek-chat` - основная модель
- `deepseek-coder` - для программирования
- `deepseek-reasoner` - с улучшенными рассуждениями

**Ollama (примеры):**
- `llama3.2:1b` - быстрая (1GB)
- `mistral:7b` - качественная (4GB)
- `llama3.1:8b` - мощная (5GB)

## 🔧 Конфигурация

### Изменение базового URL API

Если нужно изменить базовый URL API, отредактируйте файл:
```
app/src/main/java/eliseev/aiadvent/chat/di/NetworkModule.kt
```

Найдите строку:
```kotlin
.baseUrl("https://api.deepseek.com/")
```

### Изменение системного промпта

Системный промпт настраивается в `ChatViewModel.kt`:
```kotlin
ChatMessage(
    role = MessageRole.SYSTEM,
    content = "You are a helpful assistant."
)
```

## 🐛 Решение проблем

### DeepSeek API

**Ошибка: "Empty response from API"**
- Проверьте правильность API ключа в `local.properties`
- Убедитесь, что ключ активен на платформе Deepseek
- Проверьте подключение к интернету

**Ошибка: "Unknown error occurred"**
- Проверьте логи в Logcat для детальной информации
- Убедитесь, что API ключ имеет необходимые разрешения
- Проверьте лимиты использования API

### Ollama

**Ошибка: "CLEARTEXT communication not permitted"**
- Это означает, что Android блокирует HTTP трафик
- Решение уже реализовано в проекте (network_security_config.xml)
- Пересоберите проект: **Build → Clean → Rebuild**

**Ошибка: "Ошибка подключения к Ollama"**
- Убедитесь, что Ollama запущена: `ollama serve`
- Проверьте `OLLAMA_BASE_URL` в `local.properties`
- Для реального устройства используйте IP компьютера, а не `10.0.2.2`

**Ошибка: "Модель не найдена"**
- Загрузите модель: `ollama pull название_модели`
- Проверьте список моделей: `ollama list`
- Убедитесь, что в настройках указано точное название модели

**Медленная работа Ollama**
- Используйте модели меньшего размера (1b, 2b, 3b)
- Закройте другие приложения
- Убедитесь, что у вас достаточно RAM (минимум 8GB для 7b моделей)

### Общие проблемы

**Приложение не компилируется**
- Убедитесь, что все зависимости синхронизированы
- Выполните **Build → Clean Project**, затем **Build → Rebuild Project**
- Проверьте версию Android Studio и Gradle

**Конфигурация не читается**
- Убедитесь, что файл `local.properties` находится в корне проекта
- Проверьте формат: `КЛЮЧ=значение` (без пробелов вокруг `=`)
- Выполните синхронизацию Gradle после изменения файла
